## ⭐ Highest priority (P0) — DB separation and independence at deployment

> A firm principle from the manager, set at the 2026-04-24 architecture review.
> **This outranks everything else.**

- [ ] **Do not put the DB inside the dashboard's Docker project** — it must persist
  through its own separate setup.
- [ ] **The three components (AI pipeline / database / dashboard) must be fully
  independent**, each restartable on its own.
- **Background**: every `docker compose up` recreated the DB from scratch, so
  "if Docker dies, everything is gone" — state loss. The DB has to survive a process
  or Docker crash.
- **Current state**: already implemented as native postgres@16 (`:5433`) outside
  Docker, which is canonical. Docker mode is legacy.
- **Next**: **verify the deployment procedure honours this principle** —
  - Confirm in DEPLOYMENT_3PHASE that the DB persists **independently** of the
    dashboard's Docker project
  - Actually confirm DB data survives a dashboard container restart or crash
  - Confirm the DB stays independent when the AI pipeline and dashboard are each
    restarted

## 1. Latent defects — fix recommended (the `limit(1)` / text-key ordering family)

- [ ] ⚠️ **#B1 rewrite history `limit(1)` with no ordering → cross-analysis mismatch on
  re-analysis**
  - File: `app/Backend/routes_doctor.py` (~305–309, 320–324)
  - Cause: both the `SentencePrediction` coordinate → sentence lookup and the
    sentence → `llm_domain` score lookup use `.limit(1)` with no ORDER BY. The query
    is scoped by `patient_id`, so it **spans multiple analyses**.
  - Condition: when one file has been re-analysed and has **two or more analyses**.
    (Not occurring today — one analysis per file — but a realistic risk once the
    pipeline re-runs.)
  - Fix: scope by `analysis_id` and match on the (i, i2) coordinates; add ordering
    where needed.
  - Verified: files with 2+ analyses = **0**.

- [ ] ⚠️ **#B2 `score_summary` sentence-text `limit(1)` → wrong coordinates for repeated
  sentences**
  - File: `app/Backend/routes_doctor.py` (~793–801)
  - Cause: `sentence_text == source_sentence … limit(1)` (unordered) is used to
    recover (i, i2). If the same text occurs at several coordinates, one is picked
    arbitrarily.
  - Condition: when a sentence repeats in the transcript ("yeah", "okay", …).
  - Fix: determine the coordinates deterministically instead of by text match (add
    ordering, or store coordinates on `llm_domain`).
  - Verified: same text at different coordinates = **0**.

- [ ] ⚠️ **#B3/#B4 `ai_score_map` text-key collision → a multi-domain sentence's score is
  overwritten**
  - Files: `app/Backend/routes_doctor.py` (136–143),
    `app/Backend/routes_patient.py` (606–613)
  - Cause: `ai_score_map[source_sentence] = ai_score` keys on sentence text, so when
    one sentence represents two domains **the later domain's score overwrites the
    earlier one**.
  - Condition: when a single sentence is the representative for two domains (the same
    "dual-domain" family we fixed).
  - Fix: key on `(source_sentence, domain)`, or on (i, i2) + domain.
  - Verified: one sentence representing two domains within one analysis = **0**.

## 2. Latent defects — robustness (medium)

- [ ] ⚠️ **#AI5/#AI9 swallowed exceptions → silent loss of intermediate output**
  - File: `AI_physician_patient_communication/db/persistence_helper.py` (162–208)
  - Cause: the whole domain intermediate-save loop sits in a broad `try/except` that
    only warns. One bad row loses that entire domain.
  - Condition: a value exceeding a column or of the wrong type. **This is diagnostic
    data (`llm_pipeline_intermediate`), so it does not affect what patients see** —
    the non-blocking behaviour is deliberate.
  - Fix: per-row try/except, or log a failure count.

- [ ] ⚠️ **#NLP1/#NLP2 None/NA text becomes the fake sentences "None" / "\<NA\>"**
  - File: `AI_physician_patient_communication/sentence_classification/segmentation.py`
    (159)
  - Cause: the filter only checks `str(row) == "nan"`, so `None` → "None",
    `pd.NA` → "\<NA\>", and upper-case "NaN" all pass through and become fake
    sentences.
  - Condition: empty, NA, or upper-case-NaN cells in the input CSV (messy input).
  - Fix: filter with `pd.isna()`.

- [ ] ⚠️ **#NLP3 sorting breaks if the API returns scores as strings**
  - File: `sentence_classification/classification.py` (112)
  - Cause: `.pred_1` is used without a type check, so a string value makes the top-k
    sort lexicographic.
  - Condition: if the NLP API ever returns scores as strings (it does not today; this
    is defensive).
  - Fix: cast/validate with `float()`.
