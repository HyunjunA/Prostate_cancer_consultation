전립선암 프로젝트 - 작업 기록
======================================

용어 정의: 이 문서에서 "NLP"는 Michael의 r01-nlp-classifiers Docker 컨테이너를
의미합니다 — R 4.5.1 + vetiver + plumber 기반 ranger (Random Forest) 이진 분류기 5개.
모델: cp (암 예후), le (기대 수명), ed (발기 부전), inc (요실금), ius (자극성 배뇨 증상).
LLM이나 일반 NLP 라이브러리를 지칭하는 것이 아닙니다.

2026년 2월 12일:

1. 모듈 Docstring 문서화 (Part A)
   - transcript_service.py: 간략한 docstring을 상세 영문 설명으로 교체 — 7단계 파이프라인 설명, 입출력 형식, nlp_service.py 의존관계
   - nlp_service.py: 간략한 docstring을 상세 영문 설명으로 교체 — 5개 NLP 모델(cp, le, ed, inc, ius)과 임상 주제, 예측 결과 구조(.pred_1/.pred_0), connection pooling, 재시도 로직, Redis 캐싱, 환경변수
   - routes_transcript.py: 간략한 docstring을 상세 영문 설명으로 교체 — 6개 엔드포인트, 인증(X-API-Key), 이중 저장 전략(파일 시스템 + DB)

2. ML Pipeline 결과 PostgreSQL DB 저장 (Part B)
   - 문제: ML 결과({patient_id}_predictions.xlsx)가 파일 시스템(/app/uploads/)에만 저장됨, 분석 이력 추적 불가, 컨테이너 재시작 시 데이터 유실
   - 해결: 새 테이블 `transcript_analysis_log`으로 메타데이터 + xlsx 바이너리 + JSON 결과 영구 저장

   수정 파일:
   - models.py: LargeBinary import 추가 + TranscriptAnalysisLog SQLAlchemy 모델 (id, patient_id, total_sentences, top_n, context_window, model_results TEXT, xlsx_data BYTEA, source_filename, analyzed_at)
   - database_schema.sql: CREATE TABLE transcript_analysis_log + 인덱스 2개 (patient_id, analyzed_at) 추가
   - routes_transcript.py:
     * import 추가: json, select, AsyncSession, get_db, TranscriptAnalysisLog
     * POST /analyze: db 의존성 추가, 파일 저장 후 _save_to_db() 호출 (try/except, 비차단)
     * POST /analyze-batch: 성공한 파일마다 동일 DB 저장 패턴 적용
     * GET /download/{patient_id}: 파일 없을 시 DB fallback 추가
     * GET /history/{patient_id}: 신규 엔드포인트 — DB에서 페이지네이션된 분석 이력 조회
     * _save_to_db() 헬퍼: 분석마다 새 row 삽입(이력 보존), 실패 시 rollback 후 응답에 영향 없음

   설계 결정:
   - DB 실패 시에도 기존 응답 차단 없음 (try/except + rollback)
   - 동일 patient_id 재분석 시 새 row 삽입 (upsert 아닌 이력 보존)
   - 다운로드 시 디스크에 파일 없으면 DB에서 서빙 (컨테이너 재시작 복원력)
   - init_db.py가 database_schema.sql로 신규 배포 시 자동 테이블 생성

3. 자동화 테스트 스크립트
   - test_transcript_pipeline.sh 생성: 전체 파이프라인 테스트 자동화 (zsh)
   - 8단계: 사전 점검 → DB 테이블 생성 → 백엔드 재빌드 → 분석(top_n=0) → DB 저장 검증 → 2차 분석(top_n=5) → History 엔드포인트 검증 → DB fallback 다운로드 테스트
   - 클린 환경에서 10/10 테스트 통과
   - 옵션: --skip-rebuild, 커스텀 xlsx 파일 경로 지정

4. 클린 환경에서 전체 파이프라인 검증
   - Docker 컨테이너 + volume 전체 삭제 (docker compose down -v)
   - 처음부터 빌드 및 시작 (docker compose build && up -d)
   - init_db.py가 테이블 자동 생성 확인
   - processed_transcripts_sid-01.xlsx + processed_transcripts_sid-01-replica.xlsx batch 분석 (top_n=5)
   - 결과를 test_output/에 저장

5. Ground Truth 비교 — Michael의 원본 R 출력과 일치 확인
   - sid-01 결과 vs original-study-physician-predictions-top-context.xlsx (sid-01 행) 비교
   - 5개 시트(cp, inc, ed, ius, le) 전부: 모든 필드 일치
     * name, index, i, i2, speaker, text, context: 100% 동일
     * .pred_1: 최대 차이 0.00005 (float 반올림 차이만)
   - 두 output 파일(sid-01 vs sid-01-replica) name 컬럼 외 완전히 동일 확인 (동일 input 데이터)
   - 동점 처리: ius 시트 정확히 6행 반환 (pred=0.5821 동점 2개)

6. DB 저장 검증
   - SELECT from transcript_analysis_log: 올바른 메타데이터, xlsx 바이너리(262KB), JSON 결과(1.1MB)로 row 생성 확인
   - History 엔드포인트: /api/transcript/history/{patient_id}에서 타임스탬프, 파라미터 포함 페이지네이션 목록 반환
   - DB fallback: 디스크에서 파일 삭제 후 GET /download → DB에서 서빙 확인 (HTTP 200)
