2. PostgreSQL DB Storage for ML Pipeline Results (Part B)
   - Problem: ML results ({patient_id}_predictions.xlsx) stored only on file system (/app/uploads/), no analysis history tracking, data lost on container restart
   - Solution: New table `transcript_analysis_log` to persist metadata + xlsx binary + JSON results

   Files modified:
   - models.py: Added LargeBinary import + TranscriptAnalysisLog SQLAlchemy model (id, patient_id, total_sentences, top_n, context_window, model_results TEXT, xlsx_data BYTEA, source_filename, analyzed_at)
   - database_schema.sql: Added CREATE TABLE transcript_analysis_log + 2 indexes (patient_id, analyzed_at)
   - routes_transcript.py:
     * Added imports: json, select, AsyncSession, get_db, TranscriptAnalysisLog
     * POST /analyze: Added db dependency, _save_to_db() after file save (try/except, non-blocking)
     * POST /analyze-batch: Same DB save pattern per successful file
     * GET /download/{patient_id}: Added DB fallback when file missing from disk
     * GET /history/{patient_id}: New endpoint — paginated analysis history from DB
     * _save_to_db() helper: Inserts new row per analysis (preserves history), rolls back on failure without affecting response

   Design decisions:
   - DB failure never blocks the primary response (try/except + rollback)
   - Each analysis inserts a new row (no upsert — history preserved)
   - Download falls back to DB when file not on disk (container restart resilience)
   - init_db.py auto-creates table from database_schema.sql on fresh deploy
