# 2026-05-07 — V37 Per-Domain Submit Buttons

Scope: a single focused thread today — adding per-category **Submit** buttons to the Patient First Visit page (`PatientInitialVisitReportV37.tsx`) and turning the existing (dead) "Rating Progress" indicator into a working "Submission Progress" indicator. This log captures what was implemented today, what is still required to make Submit actually persist, and adjacent decisions.

---

## 1. Context

- **Page**: `app/Webapp/src/components/PatientInitialVisitReportV37.tsx` — the latest patient first-visit screen (versioned as V37 per the webapp's component-versioning convention).
- **Population**: experimental-arm patients only. They see 14 additional cognition / understanding inputs across the five clinical domains (`cp` / `le` / `ed` / `inc` / `ius`):
  - 5 VAS sliders (cp uses two; le has none; ed/inc/ius use one each)
  - 5 single-select radios (one per domain)
  - 4 multi-select checkbox groups (le/ed/inc/ius; cp has none)
- **Pre-existing state**: all 14 inputs lived in `React.useState` only. No backend write of any kind. A page reload erased every answer. The legacy "Rating Progress" indicator counted the 1–5 NIH PROMIS helpfulness rating, but the UI for that rating had been commented out — so the bar was permanently stuck at `0 / 5`.

### 2.2 Webapp container rebuild + hot-fix

- Webapp container is a **production build** with no source mount; `next dev` HMR is not in play. To pick up the V37 source change, the image was rebuilt and the container recreated:
  ```
  docker compose -f docker-compose-minimal.yml build webapp
  docker compose -f docker-compose-minimal.yml up -d webapp
  ```
- First recreate had `API_KEY` empty in the container (compose reads `${API_KEY}` from the shell env, which was unset). Backend returned `403 Forbidden` for every patient endpoint → the page rendered "Unable to Load — Failed to load summary data — Try Again". Resolved by re-running the recreate with `export API_KEY=$(grep '^API_KEY=' app/Backend/.env.native | cut -d= -f2)` first. End-to-end verified through the browser afterwards.

## 3. Outstanding — required to make Submit actually persist

The Submit buttons currently mutate local state only. The 14 inputs and the per-domain submitted flag are still lost on reload. Promoting Submit to a real persistence event needs the following 12 files.

### 3.1 Backend (5 — none of these exist yet)

| File | Action |
|---|---|
| `app/Backend/migrations/versions/010_add_patient_first_visit_responses.py` | New table `patient_first_visit_responses` (per-`(file, speaker, domain)` row, ten columns: `id`, `file`, `speaker`, `domain`, `vas_primary`, `vas_secondary`, `timeline`, `factors` JSONB, `submitted_at`, plus FK to `patient_summary(file, speaker)` ON DELETE CASCADE and CHECK constraints). |
| `app/Backend/models.py` | Add `PatientFirstVisitResponses` SQLAlchemy ORM class. |
| `app/Backend/schemas.py` | Add `FirstVisitResponseUpsert`, `FirstVisitResponseRead`, `FirstVisitResponsesGet` Pydantic schemas with VAS range validation, domain enum, per-domain `factors` whitelist (cp must be empty; le whitelist differs from ed/inc/ius), and `vas_secondary` only allowed for cp. |
| `app/Backend/routes_patient.py` | Add `GET /api/patient/first-visit-responses/{file}/{speaker}` (returns all five domains keyed) and `PUT /api/patient/first-visit-responses` (upsert one domain). Both follow the existing `update_patient_scoring` auth/ACL/select-then-upsert pattern. |
| `app/Backend/tests/integration/test_first_visit_responses.py` | Round-trip, partial update, 401, 403, 422 (invalid VAS / cp factors / le whitelist / non-cp `vas_secondary`), CASCADE delete, alembic up/down round-trip. |
