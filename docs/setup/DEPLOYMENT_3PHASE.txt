===============================================================================
 PROSTATE CANCER CONSULTATION DASHBOARD
 DEPLOYMENT_3PHASE  --  FRESH NATIVE DEPLOYMENT RUNBOOK (linear, copy-paste)
===============================================================================

 This .txt is the copy-paste runbook companion to docs/setup/DEPLOYMENT_3PHASE.md
 (same topic, same phases). It walks
 a brand-new / fully-torn-down machine all the way to a running dashboard:

     ENV SETUP  ->  PHASE 0  ->  PHASE 1  ->  PHASE 2  ->  PHASE 3  ->  VERIFY

 Run every command from the dashboard repo root unless a step says otherwise:

     cd <...>/prostate_cancer_project/Prostate_cancer_consultation_dashboard

 The two repos must be cloned as SIBLINGS:

     prostate_cancer_project/
     |-- Prostate_cancer_consultation_dashboard/   (backend + webapp)  <-- run here
     `-- AI_physician_patient_communication/        (NLP + AI pipeline)

 Legend:  $ = shell command    [once] = first install only    (!) = secret


===============================================================================
 0. WHAT YOU ARE DEPLOYING  (read once)
===============================================================================

 Three phases, each independently start/stop-able:

   Phase 1  DB + Backend     native PostgreSQL@16 (:5433) + native uvicorn (:18000)
   Phase 2  Transcripts      NLP + AI pipeline -> writes results into the DB
   Phase 3  Webapp           Next.js webapp in a Docker container (:3001)

 Native (on the host):   PostgreSQL@16 (:5433), Redis (:6379), Backend uvicorn (:18000)
 Docker:                 webapp container (:3001).  NLP classifier is NOT run
                         locally in the default REMOTE mode (Phase 2 calls a
                         remote gateway over HTTP instead).

 Dependency order:  start Phase 1 first.  After that Phase 2 and Phase 3 are
 independent of each other (Phase 2 needs only the DB; Phase 3 needs only the
 backend).


===============================================================================
 1. PREREQUISITES  [once]
===============================================================================

   - macOS with Homebrew  (Linux: use setup-native-linux.sh instead)
   - Docker Desktop running  (needed only for Phase 3 webapp)
   - git, and both repos cloned as siblings (see diagram above)
   - Network reachability to the NLP gateway host for Phase 2 REMOTE mode
     (VPN / firewall) -- see config_remote.yaml model_uri.

 The Postgres/Redis install + Python venv are created for you in Phase 0a, so
 you do NOT install them by hand.


===============================================================================
 2. ENVIRONMENT VARIABLES  [once, before Phase 0]
===============================================================================

 There are FIVE env files. Copy each *.example to its live name and fill in the
 values. The live files are gitignored -- never commit real secrets.

   2.1  app/Backend/.env                                      dashboard backend
   2.2  app/Webapp/.env                                       webapp -> backend
   2.3  AI repo .env                                          pipeline DB + local NLP
   2.4  AI repo nlp_classifier_server/gateway/.env            Phase 2 gateway secret
   2.5  AI repo ai_pipeline/.env                              Phase 2 AI substep Azure
   (+)  AI repo config_remote.yaml                            gateway URL (already in git)

 ---------------------------------------------------------------------------
 2.1  app/Backend/.env          (dashboard backend runtime)
 ---------------------------------------------------------------------------
   $ cp app/Backend/.env.example app/Backend/.env
   Then edit app/Backend/.env:

     DATABASE_URL        postgresql+asyncpg://prostatecancer_user:<PW>@localhost:5433/prostatecancer_db_native
     DATABASE_URL_SYNC   postgresql+psycopg2://prostatecancer_user:<PW>@localhost:5433/prostatecancer_db_native
     POSTGRES_USER       prostatecancer_user          (convention -- leave as-is)
     POSTGRES_PASSWORD   <PW>                     (!)  pick a strong secret:  openssl rand -hex 16
     POSTGRES_DB         prostatecancer_db_native     (convention -- leave as-is)
     POSTGRES_PORT       5433                         (native port, leave as-is)
     REDIS_URL           redis://localhost:6379/0
     API_KEY             <KEY>                    (!)  generate:  openssl rand -hex 32
     AZURE_OPENAI_ENDPOINT   https://YOUR-RESOURCE.openai.azure.com   (!) your Azure resource
     AZURE_OPENAI_KEY        <AZURE_KEY>                              (!)
     AZURE_OPENAI_API_VERSION 2024-08-01-preview
     AZURE_OPENAI_MODEL       gpt-4o
     CORS_ORIGINS        '["http://localhost:3001","http://127.0.0.1:3001","http://host.docker.internal:3001"]'
     REDCAP_API_URL      https://iredcap.csmc.edu/api/    (optional survey sync)
     REDCAP_API_TOKEN    <REDCAP_TOKEN>              (!) optional; leave placeholder to skip sync

   NOTE: <PW> must be IDENTICAL in DATABASE_URL, DATABASE_URL_SYNC and
   POSTGRES_PASSWORD. init-db-native.sh (Phase 1-a) creates the role + DB from
   these values.

 ---------------------------------------------------------------------------
 2.2  app/Webapp/.env           (webapp -> backend)
 ---------------------------------------------------------------------------
   $ cp app/Webapp/.env.example app/Webapp/.env
   Then edit app/Webapp/.env:

     NEXT_PUBLIC_API_URL    http://host.docker.internal:18000   (webapp container -> native backend)
     NEXT_PUBLIC_BASE_URL   http://localhost:3001
     API_KEY                <KEY>                  (!) MUST EQUAL app/Backend/.env API_KEY

   NOTE: if the two API_KEY values differ, the dashboard loads but shows
   "No patients found" / blank data.

 ---------------------------------------------------------------------------
 2.3  ../AI_physician_patient_communication/.env   (pipeline DB + local NLP)
 ---------------------------------------------------------------------------
   $ cp ../AI_physician_patient_communication/.env.example \
        ../AI_physician_patient_communication/.env
   Then edit it:

     DATABASE_URL        ...same target DB as 2.1 (same user/pw/host/port/db)
     DATABASE_URL_SYNC   ...same
     NLP_API_URL         http://localhost:8888    (LOCAL container; used only if PIPELINE_REMOTE=0)
     TRANSCRIPTS_DIR     data/input
     OUTPUT_DIR          data/output

   NOTE on AZURE_OPENAI_* here: the pipeline loads THIS root .env at startup, so
   these keys feed the "AZURE_OPENAI_*: configured" startup check AND act as a
   fallback for the AI scoring call. The AI substep then loads ai_pipeline/.env
   with override=True (see 2.5), so ai_pipeline/.env WINS when it sets them.
   Net: put the real Azure creds in at least one of the two -- ai_pipeline/.env
   takes precedence; using the same values in both is simplest.

 ---------------------------------------------------------------------------
 2.4  ../AI_physician_patient_communication/nlp_classifier_server/gateway/.env
      (Phase 2 REMOTE gateway secret)
 ---------------------------------------------------------------------------
   $ cp ../AI_physician_patient_communication/nlp_classifier_server/gateway/.env.example \
        ../AI_physician_patient_communication/nlp_classifier_server/gateway/.env
   Then set:

     NLP_GATEWAY_API_KEY  <GATEWAY_KEY>   (!) the X-API-Key the gateway expects.
                                              run-pipeline-watch.sh auto-reads it from here.

   (The other keys -- CLASSIFIER_CONTAINER, CLASSIFIER_URL, GATEWAY_HOST/PORT --
    only matter when you RUN the gateway server yourself, not when you are a client.)

 ---------------------------------------------------------------------------
 2.5  ../AI_physician_patient_communication/ai_pipeline/.env   (Phase 2 AI Azure)
 ---------------------------------------------------------------------------
   The Phase 2 AI scoring substep (ai_pipeline/pipeline.py) reads its Azure
   OpenAI credentials from THIS file -- config.yaml sets env_file: ai_pipeline/.env
   and loads it with override=True, so it wins over any AZURE_* exported elsewhere.

   $ cp ../AI_physician_patient_communication/ai_pipeline/.env.example \
        ../AI_physician_patient_communication/ai_pipeline/.env   # if a template exists
   Then set:

     AZURE_OPENAI_ENDPOINT  https://YOUR-RESOURCE.openai.azure.com   (!) same Azure as 2.1
     AZURE_OPENAI_KEY       <AZURE_KEY>                              (!)

   (api_version is NOT read from here -- it comes from ai_pipeline/config.yaml's
    `api_version` key, currently 2024-08-01-preview.)

 ---------------------------------------------------------------------------
 (+)  ../AI_physician_patient_communication/config_remote.yaml   (gateway URL)
 ---------------------------------------------------------------------------
   Not a secret -- already in git. Confirm the gateway URL points at your server:

     model_uri: "http://10.226.8.205:18080"

   Override per-run only with the dedicated var NLP_GATEWAY_URL (NOT NLP_API_URL).

 ---------------------------------------------------------------------------
 Which values must MATCH across files
 ---------------------------------------------------------------------------
     API_KEY            : app/Backend/.env  ==  app/Webapp/.env
     DATABASE_URL (+_SYNC, user/pw/db): app/Backend/.env  ==  AI repo .env
     AZURE_OPENAI_*     : app/Backend/.env (Try & Score)  ==  ai_pipeline/.env (Phase 2 AI substep)
                          -- two CONSUMERS, each with its own file; use the same Azure resource

 3. PHASE 0 -- FRESH PROVISIONING

 -- 0a. Provision the native stack (postgres@16 + redis + .venv) [once / post-teardown]

    Expected output (abridged) -- the script prints a banner per step + a ✓ per item:
       ===============================================================

         ✓ set port = 5433 in postgresql.conf

         ✓ redis started
       === Step 3: Python venv + backend requirements

 -- 0c. Stage transcripts for Phase 2

===============================================================================
 4. PHASE 1 -- DB + BACKEND
===============================================================================

 -- 1-a. Create the DB + migrate to head
    Creates the role/database (from app/Backend/.env), applies the schema, runs
    alembic upgrade head. No-op if the DB already exists and is at head.

    (!) macOS: RUN IT WITH  PGGSSENCMODE=disable  (see below). Without it, the
        Step-1 `pg_isready` check can falsely report "postgres NOT listening on
        localhost:5433" and abort — a GSSAPI-negotiation quirk (no Kerberos realm
        configured) that only trips pg_isready; postgres is actually fine (psql
        connects). The env var disables that negotiation so the check passes.

       $ PGGSSENCMODE=disable bash app/Backend/scripts/init-db-native.sh
       # (plain `bash app/Backend/scripts/init-db-native.sh` also works on hosts
       #  where pg_isready is not affected — e.g. the Linux caire-server.)

    Expected output (abridged) -- 6 steps, each a banner + ✓:
       === Step 0: Sanity checks
         ✓ env loaded: db=prostatecancer_db_native user=prostatecancer_user host=localhost:5433
       === Step 1: postgres reachability
         ✓ postgres listening on localhost:5433
       === Step 2: Pick bootstrap superuser
         ✓ Using superuser: <your-os-user>
       === Step 3: Create role + database
         ✓ role 'prostatecancer_user' created        (or "already exists")
         ✓ database 'prostatecancer_db_native' created
       === Step 4: Confirm app-user connection
         ✓ app credentials work
       === Step 5a: Apply database_schema.sql
         ✓ database_schema.sql applied
       === Step 5b: alembic upgrade head
         ✓ alembic upgrade head complete
         ▸ Current alembic revision (after):  016 (head)
       === Step 6: Verify schema
         ✓ Schema has 19 tables (>= 19 expected)

 -- 1-b. Start the backend (native uvicorn :18000)
    Runs preflight (postgres auth, alembic at head, redis ping) then uvicorn.

       Foreground (Ctrl-C to stop):
       $ bash app/Backend/scripts/run-backend.sh

       Detached (recommended -- survives idle SIGTERM in some shells):
       $ nohup bash app/Backend/scripts/run-backend.sh > /tmp/backend.log 2>&1 & disown

    Expected output (abridged) -- preflight runs first, then the uvicorn banner:
       === PostgreSQL reachability + auth
         ✓ postgres listening on localhost:5433
         ✓ postgres auth OK (prostatecancer_user@prostatecancer_db_native)
       === Redis reachability
         ✓ redis responds PONG
       === NLP-classifiers container (Phase 2 only -- soft check)
         ⚠ NLP container 'prostatecancer-nlp-native' not running -- dashboard will
           start fine; Phase 2 runs need it.        <-- THIS WARNING IS NORMAL in
                                                        REMOTE mode (no local container)
       === Alembic migration check
         ✓ alembic at head: 016...
         ✓ preflight passed
       ===============================================================
         Backend FastAPI (native) starting
       ===============================================================
         host:     0.0.0.0
         port:     18000
         workers:  3
         app:      main:app
         Open: http://localhost:18000/docs
       INFO:     Uvicorn running on http://0.0.0.0:18000 (Press CTRL+C to quit)
       INFO:     Application startup complete.      <-- backend is ready
    (Detached mode: the banner goes to /tmp/backend.log -- `tail -f /tmp/backend.log`.)

 -- Verify Phase 1
       $ curl -s -o /dev/null -w "%{http_code}\n" http://localhost:18000/docs    # expect 200


===============================================================================
 5. PHASE 2 -- TRANSCRIPT PROCESSING  (NLP + AI -> DB)
===============================================================================

 Default is REMOTE mode: segmentation + 5-model classification are called over
 HTTP at the gateway in config_remote.yaml (model_uri). No local NLP image
 needed. The AI scoring substep always calls Azure OpenAI.

 DE-IDENTIFICATION (recommended): run-pipeline-deid.sh first hashes the patient
 ID in each filename (data/input -> data/input_deid), then runs the pipeline on
 the hashed copies, so the DB stores HASHED patient IDs (e.g. 63514) instead of
 the original SID. Default hash is the SIMPLE one (no key). The originals in
 data/input are left untouched. See AI repo docs/DEIDENTIFICATION_EN.md.

 Prerequisites (REMOTE):
   - NLP_GATEWAY_API_KEY set (auto-read from nlp_classifier_server/gateway/.env)
   - gateway host (model_uri) reachable (VPN / firewall)
   - ai_pipeline/.env has the Azure OpenAI credentials for the AI substep (see 2.5)

 Run (RECOMMENDED -- de-identify, then process):
       $ cd ../AI_physician_patient_communication
       $ bash scripts/run-pipeline-deid.sh    # de-id (simple hash) -> pipeline; DB gets hashed IDs
       #
       # AES-SIV (stronger) hash instead of the simple one (needs DEID_KEY in .env):
       # $ DEID_METHOD=aes bash scripts/run-pipeline-deid.sh

 Run (WITHOUT de-identification -- original SIDs go into the DB):
       $ bash scripts/run-pipeline-watch.sh --dir data/input    # process once, then exit
       #
       # WATCH mode (process input/, then keep watching for new drops; Ctrl-C to stop):
       # $ bash scripts/run-pipeline-watch.sh
       #
       # LOCAL container instead of the gateway:
       # $ PIPELINE_REMOTE=0 bash scripts/run-pipeline-watch.sh

    Expected output (abridged) -- the wrapper prints its mode, then the pipeline runs:
       ▸ Starting drop-folder WATCH mode (Ctrl-C to stop).
         Drop .xlsx/.csv into data/input/ -- each is processed and archived automatically.
         Mode: REMOTE -- config_remote.yaml (NLP via the server gateway; no local container).
       ✓ NLP gateway:  http://10.226.8.205:18080
       Tokenizer: remote HTTP -> http://10.226.8.205:18080/segment
       ... per-file logs: segmentation -> classification -> AI scoring -> DB write ...
       (NOTE: the "WATCH mode" banner prints even with --dir; with --dir it still
        processes data/input once and then exits rather than watching.)

 Verify -- the log should show the gateway being used (lines above), then the DB:

 Then confirm rows landed in the DB:
       $ cd ../Prostate_cancer_consultation_dashboard
       $ .venv/bin/python app/Backend/scripts/verify_db.py

 (!) Do NOT call main_complete_pipeline_db_api.py directly with --dir/--file if
     you want the gateway -- that path runs the LOCAL container (localhost:8888)
     and bypasses the gateway. The gateway is the default only via
     run-pipeline-watch.sh.

===============================================================================
 8. STOP / TEARDOWN
===============================================================================

 Stop services (keep data):
       Backend:  pkill -f "uvicorn main:app --host 0.0.0.0 --port 18000"
       Webapp :  docker compose -f docker-compose-frontend.yml stop webapp
       Pipeline: pkill -f "run-pipeline-watch.sh"   (or Ctrl-C in WATCH mode)

 Full teardown back to truly-fresh (then start again at Phase 0):
       - kill any running pipeline/uvicorn
       - DROP DATABASE prostatecancer_db_native       (see DEPLOYMENT_3PHASE.md 0b)
       - clear data/input, data/output, data/archive
       - docker rm -f prostatecancer-webapp-native ; docker rmi <webapp image>
       - rm -rf .venv  (and app/Webapp/node_modules, .next)
       - brew services stop postgresql@16 ; brew services stop redis
       - .env files are PRESERVED (recreate them only on a brand-new machine)


===============================================================================
 9. TROUBLESHOOTING  (quick)
===============================================================================

   "No patients found" / blank dashboard
       -> app/Webapp/.env API_KEY != app/Backend/.env API_KEY. Make them equal,
          restart Phase 3.

   Backend won't start: "Python venv missing"
       -> Run Phase 0a (setup-native-*.sh) -- it creates .venv.

   Phase 2 gateway returns 401
       -> NLP_GATEWAY_API_KEY missing/wrong in nlp_classifier_server/gateway/.env.

   Phase 2 ran but dashboard still empty
       -> Transcripts not staged into AI repo data/input/ before running, or the
          pipeline used the LOCAL container path. Re-stage and run via
          run-pipeline-watch.sh.

   Try & Score on the doctor page returns 503
       -> AZURE_OPENAI_* placeholders not replaced in app/Backend/.env.

   Phase 2 finishes NLP but AI domain scores are null / missing
       -> AZURE_OPENAI_ENDPOINT/_KEY not set in ai_pipeline/.env (see 2.5). The AI
          substep reads that file, NOT the AI repo root .env.

   init-db-native.sh: "CHANGE_ME" error
       -> POSTGRES_PASSWORD still a placeholder in app/Backend/.env.

   init-db-native.sh / run-backend aborts: "postgres NOT listening on localhost:5433"
   (macOS) even though postgres IS running (psql connects, `brew services` shows started)
       -> pg_isready false negative from a GSSAPI negotiation quirk (no Kerberos
          realm). Fix: prefix the command with  PGGSSENCMODE=disable , e.g.
             $ PGGSSENCMODE=disable bash app/Backend/scripts/init-db-native.sh
          Only pg_isready is affected; psql/asyncpg fall back automatically.
