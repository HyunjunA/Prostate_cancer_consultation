 shared Linux host (caire-server, internal IP 10.226.8.205), where the runbook
 defaults DO NOT apply.

 WHY A SEPARATE FILE (this host's reality)
   - Postgres is on 5439 (5433 is taken by another project's container).
   - Redis is on 6380 (not 6379).
   - Backend is on 18001 (18000 is an unrelated user's SSH tunnel).

   - No passwordless sudo -> init-db-native.sh / setup-native-linux.sh DO NOT
     work here -> DB is created/migrated manually as prostatecancer_user.
   - The NLP "remote" gateway 10.226.8.205:18080 is THIS host's own gateway.

 ABSOLUTE PATHS used below (siblings):

   #       to use ../AI_.../.venv — it is the broken macOS one.

 -- 2b. NLP classifier container (already running; start only if missing)
   $ docker ps --format '{{.Names}}\t{{.Status}}' | grep prostatecancer-nlp-native
   # if absent:
   #   $ cd /home/choih2/test-prostate-cancer/AI_physician_patient_communication/nlp_classifier_server
   #   $ bash scripts/start.sh      # loads image + compose up + gateway

 -- 2c. NLP gateway (host process on :18080) — rebuild venv + start
   $ cd /home/choih2/test-prostate-cancer/AI_physician_patient_communication/nlp_classifier_server
   $ /usr/bin/python3.10 -m venv gateway/.venv
   $ gateway/.venv/bin/pip install -r gateway/requirements.txt
   # start it (AUTH DISABLED on this host so clients need no key — test env only):
   $ cd /home/choih2/test-prostate-cancer/AI_physician_patient_communication/nlp_classifier_server/gateway
   $ set -a; source .env; set +a
   $ export NLP_GATEWAY_DISABLE_AUTH=1
   $ nohup .venv/bin/python -m uvicorn app:app --host 0.0.0.0 --port 18080 \
         > ../logs/gateway.log 2>&1 & disown
   $ sleep 3; curl -s http://127.0.0.1:18080/ping; echo      # {"status":"online"}
   $ curl -s -o /dev/null -w "no-key /segment -> %{http_code}\n" -X POST \
         http://127.0.0.1:18080/segment -H 'Content-Type: application/json' \
         -d '{"texts":["hi. ok?"]}'                          # 200 (auth off)
   # NOTE: app.py honors NLP_GATEWAY_DISABLE_AUTH (added on this host). With auth
   #       ENABLED instead, clients must send X-API-Key = NLP_GATEWAY_API_KEY,
   #       and run-pipeline-watch.sh auto-loads it from gateway/.env.

 3. PHASE 1 -- DB + BACKEND
===============================================================================

 -- 3a. Create/seed the DB  (init-db-native.sh does NOT work here: no superuser)
    Run manually as prostatecancer_user (db owner + CREATEDB).

    FULL REBUILD (drop + recreate + schema + migrate). Stop the backend first
    because DROP needs no open connections:
      $ pkill -f "uvicorn main:app .* --port 18001"
      $ PW=<POSTGRES_PASSWORD>          # (!) your POSTGRES_PASSWORD from app/Backend/.env — never hardcode
      $ PG="host=127.0.0.1 port=5439 user=prostatecancer_user"
      $ PGPASSWORD=$PW psql "$PG dbname=postgres" -c \
          "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname='prostatecancer_db_native' AND pid<>pg_backend_pid();"
      $ PGPASSWORD=$PW psql "$PG dbname=postgres" -c "DROP DATABASE IF EXISTS prostatecancer_db_native;"
      $ PGPASSWORD=$PW psql "$PG dbname=postgres" -c "CREATE DATABASE prostatecancer_db_native OWNER prostatecancer_user;"
      $ cd /home/choih2/test-prostate-cancer/Prostate_cancer_consultation_dashboard
      $ PGPASSWORD=$PW psql "$PG dbname=prostatecancer_db_native" -f app/Backend/database_schema.sql
      $ cd app/Backend
      $ ../../.venv/bin/alembic stamp 001_baseline
      $ ../../.venv/bin/alembic upgrade head          # -> 030_add_sid_to_survey_log (head)
      $ ../../.venv/bin/python scripts/create_admin.py --username admin   # first admin (JWT login)
      $ cd /home/choih2/test-prostate-cancer/Prostate_cancer_consultation_dashboard

===============================================================================
 8. TROUBLESHOOTING (this host)
===============================================================================
   401 Unauthorized at /segment
       -> gateway auth is on and the client sent no/ wrong key. Either run via
          run-pipeline-watch.sh (auto-loads the key), OR `set -a; source
          nlp_classifier_server/gateway/.env; set +a` before a direct call, OR
          start the gateway with NLP_GATEWAY_DISABLE_AUTH=1 (2c).

   pipeline: "Python interpreter not found"
       -> the AI repo's .venv is the broken macOS one. Use the dashboard venv:
          PIPELINE_PYTHON=../Prostate_cancer_consultation_dashboard/.venv/bin/python

   init-db-native.sh fails at "Pick bootstrap superuser"
       -> expected on this host (no sudo/superuser). Use the manual steps in 3a.

   DROP DATABASE: "database is being accessed by other users"
       -> stop the backend first (pkill ... --port 18001), then terminate
          connections + DROP (3a).

   webapp 502 at /api/backend/...
       -> compose BACKEND_URL still 18000. Set it to 18001 and recreate (5b).

   webapp shows "unhealthy" but serves 200
       -> healthcheck used `localhost` (IPv6). Use 127.0.0.1 (already fixed here).

   port 5433 / 6379 / 18000 "in use" or wrong DB
       -> those are OTHER projects/tunnels on this host. This stack uses
          5439 / 6380 / 18001. Do not change the .env back to the defaults.
